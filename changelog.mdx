## How to Use This Changelog

### Add a new release

1. Pick the release date you want to publish.
2. Use a semantic version such as `v1.4.0`.
3. Summarize the most important changes first.
4. Separate new features, improvements, and bug fixes into clear sections.

### Keep entries useful

Write for readers who want a quick answer: what changed, why it matters, and whether they need to take action. If a change is small, keep it short. If it affects behavior, call it out clearly.

## Release Note Format

<Tabs>
  <Tab title="Feature Release" icon="rocket">

    Use this format when you add capabilities or expand the product surface area.

    ````markdown
    ## New Features

    - Added dashboard filters for faster navigation.
    - Introduced export support for monthly reports.
    - Improved onboarding guidance for new users.
    ````

  </Tab>
  <Tab title="Bug Fix" icon="check-circle">

    Use this format when you focus on reliability and stability.

    ````markdown
    ## Bug Fixes

    - Fixed pagination issues in long lists.
    - Resolved a layout shift on mobile devices.
    - Corrected a validation error for empty form submissions.
    ````

  </Tab>
  <Tab title="Maintenance" icon="settings">

    Use this format when changes are mostly internal or operational.

    ````markdown
    ## Improvements

    - Reduced unnecessary re-renders in the interface.
    - Cleaned up internal naming for maintainability.
    - Simplified configuration defaults for easier setup.
    ````

  </Tab>
</Tabs>

## Advanced Notes

<Expandable title="What should you include in each entry?" default-open="false">

Include changes that users will notice, such as new workflows, fixes to broken behavior, performance improvements, or configuration updates. Avoid internal-only details unless they affect the user experience.

</Expandable>

<Expandable title="How long should a release note be?" default-open="false">

Keep each release brief enough to scan in under a minute. A few bullets per section is usually enough, especially for routine updates.

</Expandable>
